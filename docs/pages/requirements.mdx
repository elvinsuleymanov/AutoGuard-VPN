# Requirements

## Server

| Dependency | Check |
|---|---|
| Docker Engine 24.x | `docker --version` |
| Docker Compose v2 | `docker compose version` |

That is the complete list. `setup.sh` runs all key and certificate generation inside
a throwaway `alpine` container, so the host needs no `openssl`, `wg`, or `curl`
binary of its own.

**Hardware:** 1 vCPU, **2 GB RAM**, 16 GB disk, public IPv4.

> **On RAM:** the shipped [`unbound.conf`](https://github.com/ElvinSuleymanov/AutoGuard-VPN/blob/main/unbound/unbound.conf)
> sets `msg-cache-size` and `rrset-cache-size` to ~249 MiB each — roughly 500 MB
> of resolver cache before Pi-hole's FTL, uvicorn, and the Docker daemon are
> counted. To run on a 1 GB host, lower both to `32m` / `64m` first.

## Open Ports

These must be reachable from the internet:

| Port | Protocol | Service |
|---|---|---|
| `51820` | UDP | WireGuard tunnel (configurable via `PORT_WG`) |
| `443` | TCP | Nginx — peer registration HTTPS API |

That is the whole internet-facing surface. Expect `443` to attract constant
automated scanning — every public IPv4 address does — but there is nothing
behind it except two API routes, so the scans find nothing. To narrow it
further, `./setup.sh --geo-allow <cc>` restricts the API to specific countries
and closes every other connection without a response. See
[Customization](/customization).

## Loopback-Only Port

| Port | Protocol | Purpose |
|---|---|---|
| `65231` | TCP | Pi-hole admin UI — bound to `127.0.0.1` on the host |

Reach it over the VPN at `http://172.29.144.30/admin`, or tunnel in:

```bash
ssh -L 65231:127.0.0.1:65231 <user>@<server-ip>
# then open http://127.0.0.1:65231/admin
```

> Published Docker ports are DNAT'd in the `nat` PREROUTING chain and therefore
> **bypass the host `INPUT` chain**. A `ufw deny 65231` on an `0.0.0.0` bind
> gives no protection at all. The loopback bind in `docker-compose.yml` is what
> actually keeps this port private — do not widen it.

## Internal Docker Ports

These are never exposed to the host:

| Port | Service |
|---|---|
| `5000/tcp` | auth-service (FastAPI) |
| `5053/udp` | Unbound DNS |

## Kernel

WireGuard requires kernel 5.6+ (built-in) or the `wireguard` DKMS module. The Compose file enables `net.ipv4.ip_forward` via `sysctls` and grants `CAP_NET_ADMIN` + `SYS_MODULE` to the WireGuard container.

## Linux Client

| Requirement | Install |
|---|---|
| `wireguard-tools` | `apt install wireguard-tools` |
| `curl` | `apt install curl` |
| `python3` | `apt install python3` |
| `iptables` | `apt install iptables` — the kill switch is built from its rules |
| root / sudo | required |

## Windows Client

| Requirement | Notes |
|---|---|
| PowerShell 5.1+ | Built in on Windows 10/11 |
| Administrator | Required for tunnel service install |
| WireGuard for Windows | Auto-installed via `winget` if absent |

> By default the server uses a **self-signed TLS certificate**, and the client
> scripts **pin** it: `setup.sh` writes the certificate's key fingerprint into
> them, and they refuse any other key. No domain or CA-signed certificate is
> needed. Install one anyway and `setup.sh` renders normal validation instead —
> see [Customization](/customization). On Windows the pinned request goes
> through the `curl.exe` that ships with Windows 10 1803 and later.
